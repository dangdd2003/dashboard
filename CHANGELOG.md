# Version 2.0 (2026-11-05)

Upgrade and hardening release. The full findings list is in [docs/REVIEW.md](docs/REVIEW.md);
the endpoint reference is in [API.md](API.md).

### Platform upgrade

- **Quarkus** 3.4.3 (EOL) → **3.40.1.1**, **Java** 17 → **21**.
- REST stack moved from `quarkus-resteasy-reactive[-jackson]` to `quarkus-rest[-jackson]`.
- **JPAStreamer** (incompatible with Hibernate ORM 7) removed for real and replaced by Panache
  (the 21 Dec 2023 entry below only removed part of it).
- Lombok 1.18.48 configured as an annotation processor; Maven wrapper updated to 3.9.11.

### Security fixes

- **Path traversal / arbitrary file read, write and delete:** clients can no longer set file paths.
  Stored paths are relative and generated by the server, each one is resolved against the data
  folder and rejected if it points outside it, and the model/resource `type` is whitelisted
  (`[A-Za-z0-9_-]{1,64}`).
- **IDOR:** the caller is identified from the JWT; the `user_id` query parameters on mutating
  endpoints are no longer used. Updates, deletes and private reads are limited to the owner or an
  admin, and endpoints without a security annotation are denied.
- **Privilege escalation:** `PUT /users/update` no longer accepts `roles`. Roles are changed only
  through the admin-only `PUT /users/{id}/roles`.
- **Uploads:** avatars must be PNG or JPEG (content type and magic bytes are checked) and at most
  5 MiB. Inference test samples are parsed as numbers and sent to the ML service as typed JSON,
  which fixes the JSON injection.
- **Password hash exposure:** `password` is removed from every user response.
- **Password policy** is now applied to the raw password, not the bcrypt hash, and
  `update-password` takes a JSON body instead of query parameters.
- **Key separation:** `keygen.sh` creates two RSA key pairs, one for signing (`sign-private.pem` /
  `sign-public.pem`) and one for encryption (`enc-private.pem` / `enc-public.pem`).
  `dashboard-security` gets only `sign-private` + `enc-public`; `dashboard-user` gets only
  `sign-public` + `enc-private`. Existing keys are kept on re-run.
- **JWT:** tokens now carry the audience `dashboard-api` (checked by `dashboard-user`) and a `jti`, and
  their lifetime is cut from 24 h to 1 h.
- Debug endpoints `/hello`, `/role` and `/role2` removed from `dashboard-security`.
- CORS origins are configurable (`CORS_ORIGINS`), Swagger UI is dev-only, and database
  credentials come from the environment.

### Correctness fixes

- Ratings: `firstname`/`lastname` were swapped in every response.
- Resources: `lastname` contained the first name.
- `GET /models/{id}` failed on MySQL 8 (`ONLY_FULL_GROUP_BY`): added the missing `GROUP BY`.
  `stars` is the average rating.
- Top-10 lists (`top10-most-use`, `top10-best-rating`, `top10-recently-use`) now have a fixed order.
- Cascade deletes: deleting a model also removes its ratings and inferences, and files are deleted
  only after the database delete succeeds.
- Paging: `pageNo` defaults to 1 and `pageSize` to 20 (max 100), results are ordered so pages are
  stable, and an empty page returns `200 []` instead of `404`.
- Error codes: unknown ids return `404`, conflicts such as an existing username or a second rating
  of the same model return `409`, and validation errors return `400`.
- Updates return the saved entity with `200`, not the request body with `202`. Create endpoints
  return `201` with the created DTO.
- Validators are thread-safe, and the password regex no longer has an accidental `)-+` range.
- One rating per user per model; `stars` must be 1..5.
- The ML service is called through a REST client (`PYTHON_SERVICE_URL`) with a 5 s connect timeout
  and a 300 s read timeout, outside any database transaction. Upstream errors return `502`, an
  unreachable service `503` and timeouts `504`.
- Upload size limit raised to 100 MB.

### Build & deploy

- Dockerfiles for both modules; images `dashboard/dashboard-user` and `dashboard/dashboard-security`.
- `docker-compose.yml` now runs MySQL 8.4 and both services with health checks and read-only key
  mounts. `quickstart.sh` builds the images and starts compose. Settings are in `.env.example`.
- Health endpoint at `/q/health/ready` (SmallRye Health).
- Configuration through environment variables: `DB_URL`, `DB_USER`, `DB_PASSWORD`,
  `DB_SCHEMA_STRATEGY`, `JWT_KEY_DIR`, `SYSTEM_FOLDER`, `PYTHON_SERVICE_URL`, `CORS_ORIGINS`.

### Breaking changes

- **Removed endpoints:**
  - `GET /hello`, `GET /role`, `GET /role2` (dashboard-security)
  - `POST /files/upload-model` (use `POST /models/create`)
  - `POST /files/upload-resource` (use `POST /resources/create`)
  - `POST /inferences/create`, `POST /inferences/model-train-eval` (stubs)
- `GET /inferences/model-train-eval-MPAP` is now `POST`.
- `user_id` query parameters on create/update/upload/ML endpoints are ignored, because the caller comes
  from the JWT. The read endpoints `/inferences/by-user` and `/resources/user_id` default to the caller.
- `POST /models/create` takes `name`, `type` and `description` as **multipart form fields**, next to
  the `model` file, instead of query parameters.
- `PUT /users/update` body is `{"userDetail": {firstname, lastname, email}}` with partial updates.
  `roles` moved to the admin-only `PUT /users/{id}/roles` with body `{"role": "admin"|"user"}`.
- `PUT /users/update-password` takes a JSON body `{oldPassword, newPassword}` and returns `204`.
  Admins may reset another user's password with `?id=`.
- `PUT /resources/update` accepts only `{"type": ...}`; `PUT /models/update` accepts only
  `{name, type, description}`.
- `DELETE /users/delete*` and `DELETE /files/delete-avatar` return `204`.
- User responses no longer contain `password`; `POST /users/create` returns `201` with the user DTO.
- Status codes: `404` for missing entities, `409` for conflicts, `200 []` for empty lists, `200`
  instead of `202` for updates.
- `/inferences` (list all) and `/resources` (list all) are admin-only.
- JWTs must contain `aud=dashboard-api`, so tokens issued by 1.x are rejected. Run `./keygen.sh`
  again, because the key file names changed.
- Model and resource rows created before 2.0 store absolute file paths. Their downloads are refused
  with `403` until the rows are migrated to paths relative to `SYSTEM_FOLDER`.
- The database schema needs unique constraints on `users.username` and on `ratings(user_id, model_id)`.
  Remove duplicates before upgrading.
- In prod, `dashboard-security` validates the schema and does not create it. Start
  `dashboard-user` first (compose already does this).
